- Создание групп каналов с независимыми UDP-назначениями (host + port).

- Проверка живости каналов через `ffprobe` перед запуском: предупреждение о «мёртвых».
- Автоматический запуск HLS-прокси с `discont_start` — MPTS переживает перезапуски overlay без полной потери потока.
- **Мониторинг в реальном времени:** PID, uptime, CPU, RAM, FFmpeg-битрейт, сетевые байты.
- **Валидация потока:** чтение UDP обратно через `ffprobe` — список программ с кодеками.
- **Данные для PBI:** готовые ячейки для копирования (IP, порт, расчётный TS bitrate).

## 🏗️ Архитектура

Система разделена на 4 логических шага, идущих по цепочке:

**1. PLAYLIST (/playlist)**
Загрузка M3U → выбор 40-50 каналов из 160 → рабочий плейлист.

**2. Smart Proxy (services/overlay_engine.py)**
Для каждого канала из рабочего плейлиста запускается HLS-прокси:
- нет правила → FFmpeg копирует поток как есть (`-c:v copy`, 0% CPU).
- активно правило → FFmpeg перекодирует с фильтром `drawtext` (libx264).

Поток доступен по адресу: `/proxy/hls/<ch_id>/index.m3u8`

**3. MPTS (/mpts)**
Создание групп каналов с UDP-назначением. Проверка каналов, мониторинг битрейта и валидация потока.

**4. MOSAIC (/mosaic) и OVERLAY (/overlay)**
Мозаика показывает Overlay-каналы, Raw-каналы и MPTS-превью. Overlay управляет правилами бегущих строк.

**Ключевой принцип:** MPTS читает `/proxy/hls/...`. Если Overlay меняет правило, прокси перезапускается, но MPTS видит `#EXT-X-DISCONTINUITY` и продолжает вещание. Канал «моргает» 1–2 секунды, но эфир не прерывается.

## 📖 Рабочий процесс

### Шаг 1: Загрузка плейлиста
1. `/playlist` → **вставь текст**, **загрузи файл** или **укажи URL**.
2. Нажми **▶ Разобрать** — появится таблица всех каналов.
3. Отметь галочками 40–50 каналов, которые пойдут в PBI.
4. **💾 СОХРАНИТЬ РАБОЧИЙ ПЛЕЙЛИСТ** — запустятся HLS-прокси (в терминале увидишь `[overlay] <hash> started in mode: COPY`).

### Шаг 2: Создание MPTS-группы
1. `/mpts` → **1. Исходный плейлист** отобразит только выбранные каналы.
2. Отметь каналы для группы.
3. Укажи **хост PBI**, **порт**, при необходимости — **сетевой интерфейс**.
4. **💾 СОХРАНИТЬ ГРУППУ**.
5. **▶ ПУСК** — запустится MPTS-процесс.
6. Проверь в VLC: `udp://@<host>:<port>`.

### Шаг 3: Мозаика (визуальный контроль)
1. `/mosaic` → выбери сетку (2×2, 3×3).
2. Для overlay-каналов плееры стартуют автоматически.
3. Для MPTS-групп нажми **▶** — запустится UDP→HLS-превью.
4. Для raw-каналов нажми **▶** — запустится HLS-превью одного канала.

### Шаг 4: Бегущая строка
1. `/overlay` → заполни параметры (текст, шрифт, цвет, скорость, расписание).
2. В поле «Каналы» выбери **только те, что уже в MPTS-группе** (иначе предупреждение).
3. **💾 СОХРАНИТЬ** — overlay-прокси перезапустится с текстом.
4. Через 2–3 секунды смотри `/mosaic` — на канале появится строка.
5. **Изменение текста** → канал моргнёт 1–2 сек → продолжит работать.

### Аварийные операции
- **⏹ STOP** в шапке — остановка всех FFmpeg-процессов.
- **🔄 RESTART** в шапке — полный перезапуск с авто-восстановлением MPTS.
- Обе кнопки требуют подтверждения.

### 💀 Провалившиеся эксперименты — НЕ ПОВТОРЯЙ

#### 1. ZMQ для «горячей» замены текста (октябрь 2026)

**Цель:** менять текст overlay без перезапуска FFmpeg.

**Что делали:** фильтр `azmq=bind_address=tcp://...` + Python-клиент `pyzmq` → отправляли `Parsed_drawtext_0 text '...'`.

**Результат:**
- FFmpeg **падал** на парсинге `bind_address` (проблемы с экранированием `:`).
- После исправления: FFmpeg **зависал** — фильтр пытался отправить кадры в сокет, который никто не читал.
- Python `context.term()` **висел вечно** — даже Ctrl+C не помогал.

**Вывод:** отказались. Используем подход **«перезапуск с `discont_start`»**. Канал моргает 1-2 секунды, MPTS переживает разрыв. Работает стабильно.

**Не начинай заново**, если нет 2-3 дней на отладку.

#### 2. `@login_required` на HLS-эндпоинтах

**Цель:** защитить `/proxy/hls/...` от несанкционированного доступа.

**Проблема:** ffprobe (внутри `api_mpts_group_start`) и FFmpeg (читает HLS для MPTS) **не имеют cookie**. Получали `302 → /login` → HTML вместо HLS → падение.

**Вывод:** HLS-эндпоинты (`/proxy/hls/`, `/mosaic/hls/`, `/mosaic/chprev/`) **намеренно без авторизации**. Для продакшена — оборачивать в reverse-proxy с HTTP Basic Auth.

#### 3. Один FFmpeg для всех каналов + overlay

**Цель:** один процесс с `-filter_complex` на N входов + drawtext.

**Проблема:** при добавлении правила на 1 канал — перезапускать всю команду. MPTS получает полный разрыв всех каналов.

**Вывод:** отдельный FFmpeg-прокси на канал. Плюс: можно включать/выключать правила точечно. Минус: 40 процессов FFmpeg на 40 каналов.

### 🧩 Ключевые архитектурные решения

#### 1. Services layer = чистый Python

`services/*.py` **не должны импортировать Flask**. Это правило. Логика отделена от HTTP, тестируется через `_check_*.py`.

#### 2. `OverlayEngine` — единая точка управления прокси

`overlay_engine.sync()` вызывается:
- APScheduler каждые 30 сек.
- Вручную при сохранении правила.
- Вручную при сохранении рабочего плейлиста.

Что делает: сверяет `cfg.working_channel_urls` + активные правила → запускает/останавливает HLS-прокси.

**`active_channels` защищён `RLock`** — Flask-запросы и APScheduler работают в разных потоках. Читать через `overlay_engine.get_active_snapshot()`, **не** напрямую.

#### 3. `discont_start` — почему MPTS переживает перезапуски

Каждый HLS-плейлист, созданный прокси, начинается с тега `#EXT-X-DISCONTINUITY`. Это говорит MPTS: «таймстемпы сброшены, но это тот же поток».

Плюс `-reconnect 1 -reconnect_streamed 1` в `build_mpts_command` — MPTS переживает 5-секундный 404 на `index.m3u8`.

#### 4. Почему `hls_list_size = 15`, а не 5

`hls.js` стартует за 3 сегмента от «живого края» (`liveSyncDurationCount: 3`). При окне 5 сегментов (10 сек) — плеер попадает на удалённые сегменты → **404 пачками**.

При 15 сегментах (30 сек) — запас достаточный, 404 нет.

**Не меняй на 5 без причины.**

#### 5. `Cache-Control: no-cache` для `.m3u8` — обязательно

Браузер кэширует HLS-плейлисты агрессивно. `hls.js` получает устаревший `index.m3u8` → ссылки на удалённые сегменты → 404.

В `serve_proxy_hls` / `serve_mosaic_hls` / `serve_chprev_hls`:
```python
if filename.endswith(".m3u8"):
    resp.headers["Cache-Control"] = "no-cache, no-store, must-revalidate"
```

Для `.ts` — `max-age=5` (короткий кеш, они не меняются).

#### 6. Мозаика: `url: null` вместо 404

`api_mosaic_sources` проверяет **существование `index.m3u8`** на диске, а не только `process.running`. Если файла нет — `url: null`. Плеер не создаётся, нет 404.

#### 7. `?v=N` в HTML для JS

Браузер кэширует JS. При изменении `mosaic.js` / `mpts.js` / `overlay.js` — **обязательно** менять `?v=N` в `<script src="...">`. Иначе правки «не применяются».
